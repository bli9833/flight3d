# 인천공항·영종도: 단계별 구현

실제 배치를 사전 가공한 뒤 단순한 건물·지면 표현으로 렌더링하는 방향입니다.
사진 기반 대용량 도시 메시를 기본값으로 삼지 않습니다.
Discussion: https://github.com/stlim0727/flight3d/discussions/216

## 현재 상태

1~3단계는 독립 미리보기로 구현됐으며, 4단계는 메인 로비의 인천공항 선택과
수동 이륙·접근·순항, 지면/건물 충돌을 연결합니다. [4단계 범위와 검증](incheon-flight.md).
아래의 1단계 실행·한계는 최초 배치 검토 기록입니다.

## 진행 순서와 완료 기준

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 — 실제 배치 검토 (완료) | 1터미널·국제업무단지 일부 2 × 2 km, 도로·건물 윤곽·복합 터미널 도형 | 출처·재현 가능한 데이터, 좌표/절단 검사, 독립 3D 미리보기와 브라우저 증거 |
| 2 — 지형·해안선 (구현) | Copernicus 표면고도와 OSM 해안선 12 × 12 km, 중심 2 km 국소 부지 보정 | 공통 좌표, 원본/보정 분리, 해안·산지 표시, 보정 경계/높이/브라우저 검증. [출처와 한계](incheon-terrain.md) |
| 3 — 가벼운 도시 표현 (구현) | 도로·주차장 지면 텍스처, 공유 건물 외벽, 공원·가로수 모형 | 같은 카메라에서 2단계 대비 화면·그리기 비용 비교. [구현·측정](incheon-city.md) |
| **4 — 비행 시나리오 (이번 변경)** | 공항 활주로·유도로·항공기 시작 위치·충돌·카메라 연결 | 실제 시설 배치/방향 확인, 지상·접근 비행·리셋 시퀀스 검증 |
| 5 — 차량과 최적화 | 가까운 차선의 제한된 차량, 공간 구역 배칭/LOD, 기기별 품질 | 전체 비행 루프의 평균/p95 프레임 시간, 메모리, 로딩 끊김 비교 |

4단계는 메인 로비의 인천 선택과 수동 비행·충돌을 연결합니다.
[시설 범위·높이 근사·브라우저 검증](incheon-flight.md). 차량과 전체 비행 성능 비교는 5단계 후속입니다.

## 현재 미리보기 실행

현재 화면은 3단계 도시 표현을 포함하며 `도시 표현`을 끄면 2단계 화면과 비교합니다.
아래 데이터 설명은 1단계 `patch.json` 기록입니다.
[2단계 지형 출처](incheon-terrain.md), [3단계 도시 표현·검증](incheon-city.md)을 함께 확인합니다.

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5186 --strictPort
```

`http://127.0.0.1:5186/incheon.html`을 엽니다. 프로덕션 빌드에도
`incheon.html`을 독립 진입점으로 포함합니다. `VITE_BASE_PATH=/flight3d/`처럼
하위 경로로 배포하면 `/flight3d/incheon.html`입니다.

로컬에서 해당 배포 경로를 검사할 때는 빌드와 preview의 base를 맞춥니다.

```sh
VITE_BASE_PATH=/flight3d/ npm run build
npm run preview -- --host 127.0.0.1 --port 5188 --base /flight3d/
APP_URL=http://127.0.0.1:5188/flight3d/incheon.html chrome-session --project flight3d node scripts/verify-incheon.mjs
```

- 항공/평면 시점, 궤도 회전·확대·이동, 세 가지 레이어 전환을 제공합니다.
- 파랑은 OSM 층수 × 3 m 추정 높이, 황토색은 높이 미상인 임시 8 m 건물입니다.
- 현재 43개 건물 객체 중 층수 추정 11개, 임시 높이 32개이며 높이 태그는 없습니다.
- 실제 배치 검토를 위해 단순한 도형을 사용합니다. 현재 화면을 최종 도시 외관으로 보지 않습니다.
- 렌더링은 조작·크기 변경 시에만 수행합니다. 표시되는 draw calls/triangles는
  이 독립 장면의 비용이며, 전체 시뮬레이터 FPS를 나타내지 않습니다.

## 1단계 배치 데이터 출처와 좌표

2026-10-26 UTC에 OpenStreetMap 공식 map API에서 받은 고정 스냅샷입니다.

```
https://api.openstreetmap.org/api/0.6/map.json?bbox=126.442,37.438,126.468,37.458
```

- 범위는 `[서쪽 경도, 남쪽 위도, 동쪽 경도, 북쪽 위도]`입니다.
- 로컬 원점은 북위 37.448°, 동경 126.455°의 **검토용 기준점**이며 공항의 측량 기준점이 아닙니다.
- WGS84 타원체의 ECEF 위치를 원점의 접평면으로 투영합니다. +X는 동쪽, +Z는 남쪽,
  단위는 m입니다. 로컬 좌표는 1 cm로 반올림하며, 원본 정확도가 1 cm라는 뜻은 아닙니다.
- 원점을 중심으로 도로 중심선과 도형을 ±1,000 m 범위로 절단합니다.
- `patch.json` 자체에는 지형 높이가 없습니다. 1단계 화면은 Y=0이었으며,
  2단계 화면은 별도 표면고도/보정 자료를 공통 좌표에 샘플링합니다.
- `source-metadata.json`의 시간은 수신 시각을 분 단위로 기록합니다. 원본 객체별 편집 시각과 다르며,
  map API 응답에는 전체 데이터베이스의 단일 기준 시각이 없습니다.

`public/scenery/incheon/`의 원본 압축 파일과 가공 JSON은 **ODbL 1.0** 데이터입니다.
저장소 코드의 MIT 라이선스와 구분합니다. 원본·생성 방법·라이선스를 같이 제공하고,
미리보기 지도 옆에 © OpenStreetMap contributors 표시와 링크를 둡니다.
[공식 출처/이용허락](https://www.openstreetmap.org/copyright).

## 재생성

```sh
node scripts/scenery/build-incheon.mjs
node --test tests/incheonData.test.js
```

네트워크 없이 원본 gzip을 풀고 SHA-256/바이트 수를 확인한 뒤 `patch.json`을 만듭니다.
최초 원본 응답은 2,667,298 bytes, 가공 JSON은 약 184 KB이며 브라우저는 가공 JSON만
요청합니다. 원본 전체를 비행 중 파싱하지 않습니다. 데이터 갱신은 별도 변경으로
출처 메타데이터와 브라우저 증거까지 함께 갱신해야 합니다.

현재 780개 객체: 건물 43, 도로 553, 활주로 2, 유도로 125, 에이프런 3,
수면 도형 2, 토지 이용 50, 공원 2. 이는 객체 수이며 도로 개수나 실제 시설 전체 수가 아닙니다.
교차로에서 여러 way로 분할되거나 패치 경계에 일부만 들어오는 시설이 있습니다.

## 배치 데이터의 알려진 한계

- OSM 도형의 완전성·최신성을 실측 검증하지 않았습니다. 영종도 전체나 인천공항 전체가 아닙니다.
- 완전한 외곽 고리만 있는 multipolygon을 조립하며, 내부 구멍 또는 누락된 구성요소가 있는
  관계 객체 8개는 제외합니다. 에이프런/녹지 일부가 빠집니다. 누락된 면을 임의로 채우지 않습니다.
  `relation/3917466`인 제1여객터미널의 분할된 외곽선은 조립해 포함합니다.
- 도로 폭은 태그가 없으면 종류별 시각화 기본값입니다. 도로의 교량·터널·층 정보는 보존하지만
  입체 구조에 반영하지 않습니다. 지형 높이는 샘플링하지만 겹친 램프의 여유고·층 분리는 후속 작업입니다.
- 배치 데이터에는 항공사진·지형·차량·건물 충돌이 없습니다. 2단계 화면의 해안선/DSM은
  별도 자료이며, 공원·토지 이용 도형도 해당 보정 지형에 맞춰 표시합니다.
- 높은 건물의 숫자·모습을 임의로 추가하지 않습니다. 실제 높이 데이터가 필요하면 한국 공공
  수치지도/건물 속성 자료의 해당 구역을 확보하고 결측률과 사용 조건을 확인합니다.

## 1단계 당시 검증과 증거

아래 결과는 1단계의 고정된 증거입니다. 현재 검증 스크립트는 3단계 화면을 검사합니다.

`headless-chrome` 스킬의 flight3d 전용 브라우저와 세션 잠금을 사용합니다.

```sh
chrome-headless --project flight3d start
chrome-session --project flight3d node scripts/verify-incheon.mjs
```

`APP_URL`, `ARTIFACT_DIR`로 URL과 출력 폴더를 변경할 수 있습니다.

1단계 당시 Intel ADL-N / ANGLE Vulkan에서 최초 장면은 **15 draw calls, 13,242 triangles**였습니다.
건물 레이어를 끄면 13 calls/9,218 triangles로 줄고 복원됩니다. 실제 UI 클릭,
시점 버튼·휠 입력, 390px 가로 넘침, 콘솔/리소스 오류를 확인했습니다.
이는 브라우저 배치 검토의 증거이며 비행 가능·실제 지형 정합·FPS 달성의 증거는 아닙니다.
