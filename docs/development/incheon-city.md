# 인천·영종도 3단계: 가벼운 도시 표현

`/incheon.html`의 중심 2 × 2 km에 도로·주차장 지면 표현, 건물 외벽과
공원·녹지 식재를 추가했습니다. 기존 12 km 지형·해안선, 건물 윤곽과 높이는 유지합니다.
`도시 표현`을 끄면 2단계의 색상 모형으로 비교합니다. `원본 DSM 비교`는 보정 전 지형을 보여 줍니다.

## 실제 데이터와 추정 표현

- `dressing.json`은 기존 고정 OSM 원본의 추가 파생 데이터입니다. 주차장 윤곽 26개와
  공항 경계 1개를 사용합니다. 12개는 `parking=surface`, 14개는 유형 미상으로 지상 주차를
  가정합니다. 다층 주차타워 2개는 지면 주차장 표현에서 제외했습니다.
- 주차선은 윤곽의 긴 변을 기준으로 생성한 **모형**입니다. 실제 구획 수·방향·면적을 검증하지
  않았고 운영 정보나 항공용 도면이 아닙니다. 길·주차장·녹지의 바깥 윤곽만 지도 데이터를 따릅니다.
- 도로 폭·차선 표시는 기존 종류별 시각화 기본값입니다. 고가·지하·교차로 층 분리는 여전히 없습니다.
- 121그루의 식재는 지도상 공원/잔디 안에 결정적으로 생성합니다. 공항 전체 경계 내부와
  주차장·건물·물·도로 주변을 제외합니다. 활주로·유도로·에이프런에서는 85 m 이상 떨어뜨립니다.
  이는 장면 배치용 제외 조건이며 실제 공항 장애물 제한 표면을 검증한 결과가 아닙니다.
  320그루 상한을 두되 현재 데이터는 제외 조건을 통과한 121그루만 사용합니다.
- 건물 형태·개수·바닥 높이는 2단계와 동일합니다. 공유 유리/석재 외벽과 지붕 재질은
  일반화한 모형입니다. 터미널의 실제 곡면 지붕이나 특정 호텔 외관을 복제하지 않습니다.

## 렌더링 방식과 비용

도로·주차장·차선·녹지·접지 그림자를 2048 × 2048 CanvasTexture 한 장에 합쳐 중심 지형에
매핑합니다. 2 km에 약 0.98 m/texel이므로 지상 근접 시 흐려질 수 있습니다. 차선과 주차선은
텍스처의 안티앨리어싱에 의해 희미해질 수 있으며 입체 모델이 아닙니다.
주변 지형은 기존대로 표시하고 자연/보정 표고를 바꾸지 않습니다.

건물은 세계 m 기준 UV를 써서 긴 터미널 벽에서도 창문 크기가 같이 늘어나지 않게 합니다.
전체 건물을 유리·석재·지붕 최대 3개 배치로 병합합니다. 나무는 기존 Flight3d의 불투명
저상세 oak geometry를 공유하는 InstancedMesh 하나입니다. 개별 광원·투명 잎·실시간 그림자 패스를 추가하지 않습니다.
텍스처에 구운 접지 그림자는 고정된 낮 시점용 표현입니다.

지면 텍스처는 RGBA8 + 밉맵 가정 **22,369,621 bytes(약 21.33 MiB)**의 추가 저장 비용입니다.
외벽 패턴은 공유 256px 텍스처 2개로 약 0.67 MiB입니다. 이는 형식 기반 추정이며 실측 VRAM은 아닙니다.
텍스처/나무는 코드에서 생성하므로 별도 사진·모델 다운로드는 없습니다. 추가 파생 JSON만 읽습니다.
OSM 파생 지면은 출처를 표시하고 원본·생성 도구를 제공하며 기존 MIT 나무 모델을 재사용합니다.
[데이터별 고지](../../public/scenery/incheon/LICENSE.md).

비교용 2단계 메시도 메모리에 보관합니다. 화면에서는 현재 모드의 메시만 그립니다.
모드 변경 때 메시를 다시 만들지 않고, 레이어 변경으로 지면 텍스처를 다시 만들 때는 이전 텍스처를 해제합니다.
이 비교 기능을 유지한 상태의 geometry/texture 수를 증거에 기록했습니다.

## 재생성과 실행

```sh
npm ci
node scripts/scenery/build-incheon-dressing.mjs
node --test tests/incheonDressing.test.js tests/incheonTerrain.test.js tests/incheonData.test.js
VITE_BASE_PATH=/flight3d/ npm run build
npm run preview -- --host 127.0.0.1 --port 5193 --base /flight3d/
```

`http://127.0.0.1:5193/flight3d/incheon.html`을 엽니다. Python·API 인증키·외부 데이터 재조회는 필요 없습니다.
주차장 파생 데이터는 원본 SHA를 검증하고 오프라인에서 재생성합니다. 1·2단계 데이터 파일은 수정하지 않습니다.

Intel ADL-N / ANGLE Vulkan, DPR 1. UI 레이아웃이 두 모드에서 같은 캔버스 크기를 유지하는지 확인하고,
원경·근접 각각 같은 카메라/해상도에서 `2단계 → 도시 → 도시 → 2단계` 순서로 측정했습니다.
각 패스 5회 준비 렌더 후 40개 표본입니다. 시간은 `renderer.render` + `gl.finish` 벽시계 시간으로,
GPU 타이머 쿼리·초기 생성/텍스처 재생성 비용·전체 비행 루프 FPS가 아닙니다.

| 시점 | 2단계 calls / triangles | 도시 calls / triangles | 패스별 중앙값 ms: 2단계 → 도시 |
| --- | --- | --- | --- |
| 원경 | 17 / 307,180 | 9 / 172,794 | 0.9–1.4 → 0.8–0.9 |
| 근접 | 16 / 305,822 | 9 / 172,794 | 0.8–0.9 → 0.7 |

표본과 패스 순서를 그대로 공개합니다. 짧은 벽시계 측정에는 GPU 상태와 실행 순서에 따른 변동이 있으므로
비율을 전체 시뮬레이터 FPS 향상으로 해석하지 않습니다. 기하 비용 감소와 텍스처 메모리 증가의 절충입니다.

브라우저 검사는 실제 체크박스, 지면 픽셀 해시의 변경/복원, 두 시점 비교, 원본 DSM 전환,
메시/텍스처 수 증가 여부, 휠·모바일 가로 넘침과 캡션 겹침, 런타임/리소스 오류를 확인합니다.
Node 테스트는 파생 데이터 재현성, 주차타워 제외, 식재 영역·이격, 공유 외벽의 경계 보존과
UV 크기, 인스턴스의 지형 높이를 검사합니다.

현재는 독립 미리보기입니다. 다음 4단계는 실제 공항 시설과 비행·충돌 시나리오 연결입니다.
차량과 전체 비행 프레임 시간 검증은 그 뒤 단계로 유지합니다.
