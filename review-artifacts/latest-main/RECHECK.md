# 최신 main 재검증

기준: `1f6f20b` (`fix(flight): eliminate cockpit screen jitter, fix 180-deg spin, and smooth demo flight`). 기존 검토 브랜치의 보고서 커밋을 이 main 위로 rebase했다. 이전 보고서와 루트의 캡처는 `b491a6a`의 과거 증거이며 최신 상태의 결함 목록이 아니다.

## 수정 확인

- 롤 감쇠: 각속도와 반대 방향의 모멘트가 발생한다. ±0.1 rad/s의 roll rate에 ∓288,474 Nm가 나와 기존의 부호 오류가 해소됐다 (`math-checks.json`).
- 접근 중심선 지형: x=-6500~-1900, z=0을 10m 간격으로 확인했다. 목표 3° 경로 아래로 최소 36.95m 여유가 있고 경로 침범 표본은 0개다. 기체 전체 폭·횡방향 오차까지 검증한 결과는 아니다.
- 데모 선회: 메인 루프 기록에서 41초 roll 20.04°, 51초 roll 12.20°. 이전 -82° 선회 및 180° 뒤집힘은 이 실행에서 재현되지 않았다.
- 카메라 계산 전 최신 기체 월드 행렬을 명시적으로 갱신하고 지상에서 G 기반 머리 움직임을 억제하는 변경을 확인했다. 실제 초기 프레임 재측정 결과는 아래 추가한다.
- `npm test`: 6개 테스트 파일 통과, `npm run build`: 성공. 번들 크기 경고는 남아 있다.

## 남은 핵심 문제: 활주로 밖 접지를 정상 착륙으로 처리

`natural-flight.json`은 새로운 main의 `animate()`를 60Hz로 실행한 기록이다. 내부 120Hz 물리와 렌더러의 월드 행렬 갱신을 유지하고 GPU 제출·계기판 그리기만 생략했다. 실제 GPU 프레임 속도나 시각 품질 검증과 구분한다.

- 93초: rollout 단계(5), `onGround=true`, 위치 x=-3645.76m, y=65.20m, IAS=135.74KT.
- 실제 활주로는 길이 3200m, 중심 x=0이라 서쪽 끝은 x=-1600m다. 즉 활주로 약 2046m 앞 지형에 이미 접지한 상태다. 데모가 가정하는 threshold(-1350m)와 비교하면 약 2296m 앞이다.
- 105초: 데모 종료, 위치 x=-3212.29m, IAS=7.51KT. 안전 정지 조건인 5KT보다 빠른데 12초 시간 제한으로 완료된다.
- 최종적으로 x≈-3172m의 활주로 밖 지형에서 정지한다. 이번 실행에서 crash는 없지만 정상 활주로 착륙 완주는 아니다.

접근 고도/강하율 추적과 preset trim 유지, 지속 플레어를 확인하고, touchdown 성공에 실제 활주로 영역·기어·속도·강하율 조건을 넣어야 한다. 단순 `onGround` 및 시간 초과는 착륙 성공 기준이 될 수 없다.

## 기존에 보고한 나머지 항목

시간 기반 단계 전환, 플레어가 다음 접근 guidance에 덮어써지는 구조, preset의 aero trim이 controls trim으로 덮어써지는 구조, 기본 요크 배치 및 HUD/배너 고정 위치는 이번 main 변경에서 수정되지 않았다. 모두 재수정됐다고 판단해서는 안 된다.

## 실제 초기 렌더링 프레임 비교

실제 WebGL 렌더링을 유지한 첫 8개 프레임(시뮬레이션 약 0.2~0.9초)을 수집했다. `startup-jitter.json`에서 모든 프레임의 기체 상대 카메라 Y는 0.82m로 일정하며(부동소수점 오차 수준), head offset과 카메라/렌더 간 행렬 지연은 모두 0이다. 이전 버전의 약 12.4cm 상대 높이 변동이 사라졌다. `startup-jitter-0.png`, `startup-jitter-1.png`, `startup-jitter-2.png`에서도 요크와 계기판의 화면 위치가 고정돼 있음을 직접 확인했다. 바깥 활주로 시야에는 착륙장치에 의한 작은 기체 자세 변화가 보이지만 콕핏 내부의 상대 떨림과는 구분된다.

이 관찰 구간에서는 시작 직후 콕핏 떨림이 재현되지 않았다. 모든 기기·FPS 조건 및 이후 비행 구간 전체의 플리커가 없다는 의미는 아니다.
